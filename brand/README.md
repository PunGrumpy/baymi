# Brand assets

```text
src/            the generator, and the only code here
logo.png        authored: the master the banner is built from
fonts/          authored: vendored upstream releases
banner.gif      generated by src/banner.ts
banner.png      generated: the still the README serves under reduced motion
banner.shader-lab.json  generated: the Shader Lab composition on its own
```

Which of those are generated is the thing worth knowing before editing one, so `.gitattributes` says it too: the generated three are marked `linguist-generated`, which collapses them in pull request diffs rather than showing 350 KB of binary noise. Nothing in the running agent reads any of it. eve has no logo, avatar, or icon setting anywhere in `defineAgent` or elsewhere, and it serves no static directory. These live here rather than in `public/` for that reason, since `public/` in a Vercel repository reads as “served at the root”, and they are not.

Baymax is the reference throughout, since that is where the agent's name and its logo come from: soft, white, inflated, and unhurried. The banner does not try to redraw any of that. It uses the logo itself, and everything around it is set up to stay out of its way.

## logo.png

The master is 1024x1024, palette-encoded at quality 90, which is visually identical to the original truecolor export and a fifth of its size. It has no alpha channel, and its background is a soft vignette from `#dcdee0` to `#f4f5f4` rather than a flat colour, so it cannot be keyed out: the body's own white falls inside that range. Composite it on a light background, or fade an edge as the banner does.

It has three homes, all of them outside this repository, and all uploaded by hand:

| Where | What it becomes | Set at |
| --- | --- | --- |
| GitHub App `baymiai` | The avatar beside `baymiai[bot]` on every comment it posts | Settings → Developer settings → GitHub Apps → Display information |
| Slack app | The icon beside its name in the digest thread and in DMs | Slack app settings → Basic Information → Display Information |
| Linear OAuth app | The agent’s avatar in an Agent Session | Linear settings → API → OAuth applications |

The GitHub one is worth doing first: it appears on every pull request summary and every answered mention, which is where most people will see the agent at all.

Re-export from the master rather than from a copy that has been through an upload, and keep it square.

## Running the generators

`brand/` is its own package. Its toolchain is a headless browser, a native image library and a WebGPU shader runtime, none of which the running agent needs, so keeping it out of the root manifest means neither a fresh clone nor CI pays for it.

```bash
cd brand
bun install
bun run banner          # banner.gif, banner.png, banner.shader-lab.json
bun run banner:preview  # PNG stills instead, for iterating on the design
bun run typecheck
```

Deliberately **not** a workspace yet. Adding `brand` to `workspaces` in the root `package.json` would put sharp, three and playwright back into every `bun install --frozen-lockfile` in CI. When this repo moves to Turborepo that changes, and the manifest here is already the right shape for it.

Versions are pinned rather than floated because the output is committed. The same input produces the same bytes only if the encoder is the same: moving sharp between 0.34 and 0.35 rewrites every PNG with identical pixels, which shows up as a diff nobody can review.

It needs a Chromium with WebGPU. `bunx playwright install chromium` provides one; `BANNER_BROWSER` points at a different binary.

The root `tsconfig.json` covers only `agent/` and `evals/`, so this package carries its own. It is worth running: the first time it ran it turned up that `gifenc` ships no types, which had left the whole encoding path as `any`. `gifenc.d.ts` declares the surface used here, and the contract it makes explicit is the one that had already caused a bug: the palette given to `applyPalette` and the palette given to `writeFrame` are not the same array.

Nothing in CI runs it, because CI never installs this package. Run it here after changing anything under `brand/`.

## banner.gif

Baymi's own face, bled off the right edge, on a ground that drifts. 1000x266, 36 frames at 12 fps, 530 KB.

Every position in `src/banner.ts` is written in an 800x213 grid, the one the layout was tuned in, and `SCALE` decides what it renders at. The README serves the banner at `width="100%"` and GitHub's markdown column is around a thousand pixels, so `SCALE` is `1.25`: at 800 the browser stretched the asset to fill the column and softened the type, and at 1000 it does not. Raising it to `2` would cover retina too, at four times the file, which a banner does not earn.

The face is `logo.png` itself rather than anything redrawn. It runs off the right, top and bottom edges on purpose: only its left side lands inside the frame, so that is the only edge that has to be hidden, and one horizontal fade does it. Keying out the logo's own background is not an option here, because that background is a soft vignette running from `#dcdee0` to `#f4f5f4` and overlaps the white of the body itself.

The ground behind it is a [Shader Lab](https://eng.basement.studio/tools/shader-lab) composition rendered on WebGPU by `@basementstudio/shader-lab`: five points a few percent apart in lightness, warped slowly. It is the paper, not the subject. Anything with more contrast competes with the face, which is the thing the banner is for.

The only other motion is a warm bloom over the eyes, pulsing once across the loop. Drifting the whole logo a few pixels was the first attempt and it tripled the GIF, because a one-pixel shift rewrites every pixel of the body, for motion that was almost invisible. The glow covers a twelfth of the area and quantises cheaply.

`banner.png` is the same picture, frozen at the GIF's first frame. The README serves it through a `<picture>` element under `prefers-reduced-motion: reduce`, since a GIF loops forever with no way to pause it.

`banner.shader-lab.json` is the ground on its own, in the shape the Shader Lab editor exports. Open it in the editor to change it by hand, or drive the editor through the `shader-lab` MCP server registered in `.mcp.json`, which needs a tab open at `https://eng.basement.studio/tools/shader-lab?agent=1`. `banner.ts` holds the same composition as `COMPOSITION` and rewrites the JSON on every run, so the two cannot drift.

### Colour

| Role | Value | Measured |
| --- | --- | --- |
| Paper | `#eef0ee` | The ground the logo was rendered on, so the two meet without a seam |
| Tagline | `#23211f` | 9.5:1 against the worst background pixel it covers in any frame, which clears AAA |
| Wordmark | `#666059` | 4.7:1 the same way |

Near-black with a trace of warmth rather than pure black, which on this paper reads as a hole punched in it. Both ratios are measured against the darkest pixel the type actually sits on across all 36 frames, not against the flat paper colour, because the ground drifts behind the text. The wordmark needs the full 4.5:1 rather than the 3:1 a heading gets: Geist Pixel at 22px is not large text under WCAG. Re-measure after any change to the composition, not just after a change to the type.

### Type

[Geist](https://vercel.com/font) SemiBold for the tagline and Geist Pixel Square for the wordmark, both vendored under `fonts/` with the SIL Open Font License (`fonts/OFL.txt`). Only the two faces the banner actually renders are checked in.

Square rather than Line: Geist Pixel Line is a hairline outline face, and at 22px in a muted grey it reads as thin sans rather than as pixels. Square is solid and holds the letterform at that size.

Fonts are handed to sharp as files, not looked up by name. The obvious approach, writing a fontconfig config and exporting `FONTCONFIG_FILE`, does not work from inside the script: assigning to `process.env` does not reach the `getenv` that fontconfig actually reads, so every vendored family silently falls back and the banner renders in whatever the machine has. It fails quietly, which is the dangerous part. sharp's text API takes a `fontfile` and registers it through `FcConfigAppFontAddFile`, which needs no environment at all.

That registration is not visible to the SVG renderer, so every run of text goes through the text API and is composited at a known position rather than being laid out in the overlay SVG. The overlay SVG carries only the fade, which needs no fonts.

### Regenerating

Regenerate with `bun run banner`, or `bun run banner:preview` to write PNG stills instead of encoding the GIF, which is the faster loop while you are changing the design.

Three more things about the pipeline are worth knowing before you change it:

- **Frames are read back through a render target, not off the canvas.** A WebGPU canvas is invalidated once the browser composites it, so `toDataURL` on the runtime's own canvas returns a blank image
- **The loop is a dissolve, not a cycle.** The ground runs on an open clock and never returns to its starting state, so the script renders ten frames past the end and plays them back under the opening ten. The eye pulse is a whole sine cycle and needs none of that
- **The transparent palette slot is never used for mapping.** Frames carry only what changed, and `dispose: 1` fills the rest from the previous frame. Hand `applyPalette` a palette with the transparent entry appended and any pixel whose nearest colour is that entry gets erased into whatever came before, which reads as streaks smeared across the picture

Check a change against `preview-0.png` and `preview-18.png` together, not one still, since the ground drifts across the loop and the GIF starts from frame 36 rather than frame 0.

The render is deterministic: the same script produces the same bytes on any machine, and a rerun that changes nothing shows up as no diff.
